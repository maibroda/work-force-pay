# E3b explain-back note: the module switch (built; every module starts OFF)

Written 2026-11-03. For the founder. This touches access control (it is what makes the E3a guards act), so it is a critical change under `CLAUDE.md`. **With every module OFF, which is how it starts, nothing is checked and nothing changes for anyone.**

1. **What it does.** A platform setting, per module, with three states: OFF (nothing checked), REPORT (everything is let through and a log line says what would have been refused), ENFORCE (a company that did not buy the module is refused). It is stored in two new tables, `EntitlementSwitch` (one row per module that is not OFF) and `EntitlementSwitchEvent` (the history), both for the whole platform, not per company.
2. **Who may change it.** Platform staff (`SUPER_ADMIN`) only. A bureau's administrator can change its own clients' subscriptions (E2) but cannot change whether subscriptions are checked, and a company's administrator can do neither. The page (Settings, Module switch) is in the menu for platform staff only, and the service checks the role again.
3. **The refusal you asked for (answer 2 of 2026-11-03).** REPORT and ENFORCE are **refused while any company has no subscription**, and the message names the companies (by code) to give one to. It is checked inside the same database transaction as the change, so a company made a moment earlier counts. OFF is always allowed. The page also shows the warning with the companies' codes.
4. **How it reaches a request.** On each request the session loads the switch. While every module is OFF it gives the request nothing to check (one small lookup, no subscription read) and every E3a guard allows. Once any module is not OFF, the request is given the company's modules today (from E2, so an ended module does not count) and the list of modules being checked. A company with no subscription is held to the core only; the refusal in point 3 stops that being the case when a module is first turned on, and this covers one made afterwards by a route that forgot a subscription.
5. **What a refused person sees.** A refused page sends them to the "Not part of your plan" page naming the module and saying to ask whoever looks after their account. A refused action returns the same words and does not run. The menu hides the pages of a module that is enforced and not bought (REPORT hides nothing).
6. **History.** Every change is recorded (module, from, to, who, why) in a table the database refuses to update or delete; a reason is required. The audit log is not used because it belongs to a company, and this is platform-wide.
7. **What could go wrong.** (a) Turning a module to ENFORCE with a wrong declaration locks a company out of something it paid for: use REPORT first, read the log lines (`entitlement_would_refuse`), then ENFORCE, and set it back to OFF if anything is wrong; OFF takes effect on the next request. (b) The 12 scheduled jobs are not guarded yet (E3c): enforcing a module does not stop its job running for a company that did not buy it. (c) Nobody but you decides when to turn anything on; I will not.
8. **Worked example.** Every company has a subscription. Platform staff set Analytics to REPORT, reason "Looking first". A company on Payroll Essentials opens Payroll Analytics: it opens as before, and a log line says Analytics would have been refused for that company. A week later they set Analytics to ENFORCE: the company's menu no longer shows Analytics, its Payroll Analytics page sends it to "Analytics is not part of your plan. Ask whoever looks after your account to add it.", and its export route returns the same words with a 403. A company that bought Analytics sees no difference. A new company is made without a subscription: its first request is held to the core and the platform page lists it.
9. **Which tests prove it.** `tests/integration/entitlements-switch.test.ts` (platform staff only; starts OFF; refused while a company has no subscription, naming it; core, unknown module and mode, no reason and "already" refused; history refused by the database; what a request is given, ended modules and a company with no subscription) and `tests/unit/entitlements-guard.test.ts` (menu hiding; the session and layout wiring).
10. **Honest limits.** The page has not been looked at in a browser, and enforcement has not been exercised end to end in a running app. The full suite, build and smoke results are in the pull request.
