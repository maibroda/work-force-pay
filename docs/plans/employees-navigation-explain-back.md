# Explain-back note: Employees as one menu entry, and an employee record that shows everything (screen change only)

Written 2026-11-04. For the founder. This changes what is shown on screen, including sensitive personal records, so it touches access control display. **No data, payroll, statutory or permission rule is changed.**

1. **The menu.** The sidebar's "Workforce / Personnel" group now has one entry, **Employees**. Import Employees, Categories, Departments, Bank, Pension, Tax, Detail change requests, Next of kin & emergency, Guarantors, Dependants & beneficiaries, Assignments and Org chart sit inside it as a **row of tabs across the top of the Employees pages**. Import employees is one of those tabs.
2. **Who sees which tab.** A tab appears only to a role that may open its page (the same permission the page already requires: for example Bank, Pension, Tax and Next of kin need the sensitive-records permission) and only while the module is on for the company. Every page still checks the same on the server: hiding a tab is not the control. A test pins that no tab is looser than its page.
3. **The employee's own record, Overview.** It now shows all of that person's information in sections: Personal details, Employment, Current assignment, **Bank information, Pension information, Tax information, Next of kin & emergency contacts, Guarantors, Dependants & beneficiaries**. The last six are shown **only to people with the sensitive-records permission** (before, bank, tax and pension showed as dots to others; now the section is simply not there for them). The full tabs remain for editing, now named for what they hold ("Next of kin, guarantors & dependants", "Detail change requests").
4. **Logging.** Opening the Overview as someone with the sensitive-records permission is now recorded as a personal-records access as well as an identifiers access, exactly as opening the Contacts tab already was.
5. **What could go wrong.** A role that used to see masked bank details on the Overview now sees no bank section: nothing sensitive is shown to anyone who could not see it before. A very long contacts list makes the Overview longer: each section has an "Add or edit" link to its tab.
6. **Worked example.** An HR administrator opens EMP-000001. The page shows personal and employment details, the current site, the bank, pension and tax details, one next of kin and two emergency contacts, a guarantor with its status, and a dependant, and an "Add or edit" link on each of the last four. A payroll officer without the sensitive-records permission opens the same record and sees only the personal, employment and assignment sections.
7. **Which tests prove it.** `tests/unit/employees-navigation.test.ts`: the sidebar has one Employees entry and none of the moved pages; the tab row has every moved page under the names given, links only to pages that exist, is never looser than a page's own permission, and shows only on the section pages (not on a record); and the Overview has each section with the six sensitive ones behind the sensitive check in the page.
8. **Honest limits.** The tests check the structure and the source of the page, not the rendered screen; I looked at the screen in a browser (see the pull request).
